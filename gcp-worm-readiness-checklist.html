01

Governance, IAM & Risk Safeguards

0/5 Not started

Decide what is allowed into permanent storage, and who can touch it, before anything becomes undeletable.

  • Your teamPrivacy counsel sets infoType scope and redaction-versus-tokenization policy.

    Mechanism

    Sensitive Data Protection deidentifyContent driven by stored inspection and de-identification templates, called inline from the ingestion service or via the Dataflow DLP-to-BigQuery template; infoType detectors and transformations are declarative.

    Watch forRedaction missed here is unfixable: once inside a locked bucket the data cannot be erased for a GDPR or CCPA request.

  • Mechanism

    Cloud Logging sink inclusion and exclusion filters in Terraform google_logging_organization_sink (filter, exclusions) using severity predicates; fully deterministic and diffable in code review.

    Watch forOver-aggressive exclusion silently destroys evidence, so filters belong in version control and code review, never in a console edit.

  • Mechanism

    Aggregated google_logging_organization_sink with include_children = true pointed at one dedicated project, provisioned by a Terraform project factory; Org Policy pins the destination.

    Watch forThe separation is only real if workload-project admins hold no IAM on the compliance project.

  • Mechanism

    google_organization_iam_custom_role with an explicit permission allowlist (logging.logEntries.create, bigquery.tables.updateData), backstopped by IAM v2 deny policies (policies.createPolicy), asserted pre-deploy with Policy Simulator in CI.

    Watch forWithhold bigquery.jobs.create from the ingestion identity: DML runs as a query job, the Storage Write API does not, so appends survive.

  • Mechanism

    Resource Manager liens via POST cloudresourcemanager.googleapis.com/v3/liens with restrictions: [resourcemanager.projects.delete], or Terraform google_resource_manager_lien; the caller needs resourcemanager.projects.updateLiens.

    Watch forA lien is reversible by anyone holding resourcemanager.projects.updateLiens, so deny that permission or the safeguard can remove itself.

02

Storage & Ingestion Pipeline

0/4 Not started

Stand up the write-once tiers and the append-only path that feeds them.

  • Your teamCompliance officer attests the retention window under SEC 17a-4(f) and authorizes the lock.

    Mechanism

    Terraform google_storage_bucket with retention_policy { retention_period, is_locked }, or the JSON API buckets.lockRetentionPolicy; per-object mode needs a bucket created with --enable-per-object-retention, then retention mode Locked.

    Watch forLocking is irreversible: the period can only be increased, never shortened or removed, and the bucket cannot be deleted until every object ages out.

  • Mechanism

    Terraform google_bigquery_table plus a client calling CreateWriteStream with type COMMITTED and AppendRows carrying per-stream offsets; a retried offset returns ALREADY_EXISTS instead of duplicating the row.

    Watch forCommitted-stream rows are queryable as soon as BigQuery acknowledges the append, so offsets deliver exactly-once without any staging table.

  • Your teamSecurity lead approves the irreversible bucket lock and the retention-day figure.

    Mechanism

    gcloud logging buckets create --locked --enable-analytics --retention-days, or Terraform google_logging_project_bucket_config with locked = true and enable_analytics = true; both flags are one-way.

    Watch forLocking and the Log Analytics opt-in cannot be undone, and a locked bucket resists deletion until every entry has aged out.

  • Your teamEngineer decides which prompt, RAG and tool payloads are safe to persist immutably.

    Mechanism

    OpenTelemetry SDK emitting gen_ai.* semantic-convention attributes over OTLP into Cloud Trace and Cloud Logging; the conventions remain Development status, gated behind OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental.

    Watch forNo GenAI attribute is Stable yet, so pin the version — and capturing raw prompts collides directly with task-1's redaction scope.

03

Cryptographic Ledger & Anchoring

0/5 Not started

Make every record provably in sequence and provably signed, so tampering shows up as broken maths rather than a judgement call.

  • Your teamKey custodian signs off protection level, rotation and signer/verifier separation of duties.

    Mechanism

    Terraform google_kms_crypto_key with purpose = ASYMMETRIC_SIGN and version_template { algorithm = EC_SIGN_P256_SHA256, protection_level = HSM } through projects.locations.keyRings.cryptoKeys.create, on FIPS 140-2 Level 3 Cloud HSM.

    Watch forGoogle-generated HSM keys need no ceremony — the private key never leaves the HSM. A real ceremony applies only to material imported via importJobs.

  • Mechanism

    Application code in the ingestion runtime (Cloud Run): RFC 8785 canonical JSON, SHA-256, and a prev_hash column carried in the table schema; golden-vector unit tests in Cloud Build.

    Watch forPin the canonicalization spec and sequence writes per stream — a re-serialization change or a concurrent append breaks the chain retroactively.

  • Mechanism

    projects.locations.keyRings.cryptoKeys.cryptoKeyVersions.asymmetricSign in digest mode, called by the ingestion service holding roles/cloudkms.signer, before the committed-stream append is made.

    Watch forSign Merkle roots, not individual records: asymmetricSign is billed and rate-limited per call, so batching is what makes this affordable at volume.

  • Mechanism

    Cloud Scheduler triggering a Cloud Run job that runs BigQuery EXPORT DATA to compressed Parquet, or a table extract job, writing into the retention-locked GCS bucket.

    Watch forExport object names must be idempotent: overwriting an object still under retention fails with 403 retentionPolicyNotMet, so a blind retry hard-fails.

  • Your teamCounsel selects and contracts a TSA whose tokens the regulator will accept.

    Mechanism

    No native GCP timestamping authority exists. The RFC 3161 client automates fully (TSP request over the signed Merkle root, token stored alongside it); the authority itself is a third-party contract.

    Watch forSelf-hosting a TSA such as sigstore/timestamp-authority is trivial on Cloud Run but forfeits the third-party neutrality that makes the anchor worth having.

04

Verification & Operational Testing

0/5 Not started

Prove the controls hold by attacking them, and keep watching once they do.

  • Mechanism

    Cloud Scheduler plus a Cloud Run job in a separate project running the verifier, reading through the BigQuery Storage Read API and cryptoKeyVersions.getPublicKey with only roles/cloudkms.publicKeyViewer.

    Watch forGive the verifier its own project and a read-only identity, or it inherits the very trust it exists to test independently.

  • Mechanism

    Cloud Build step issuing bq query DELETE and UPDATE as a deliberately privileged service account and asserting accessDenied; re-run on a Cloud Scheduler cadence, with Policy Simulator checks pre-deploy.

    Watch forThis is the test that catches task-4 drift, because a role granting appends can also authorize mutating DML if job creation is allowed.

  • Mechanism

    CI job asserting that gcloud storage rm exits non-zero against a still-retained object, matching on the returned reason code rather than on exit status alone.

    Watch forThe real failure is HTTP 403 retentionPolicyNotMet, not 412 Precondition Failed — assert on that reason code, not the checklist's wording.

  • Mechanism

    Cloud Build job seeding a mutated fixture into a disposable non-production dataset, then asserting the verifier exits non-zero and names the expected broken offset in the chain.

    Watch forRun this only against a throwaway dataset: injecting tampered payloads into the real locked ledger is itself an unremovable audit event.

  • Your teamOn-call engineer judges whether a failure is corruption, key rotation drift, or breach.

    Mechanism

    The verifier emits a log-based or custom metric; google_monitoring_alert_policy with notification channels fires on any signature failure or sequence gap, optionally surfaced in Security Command Center.

    Watch forA signature failure is not self-explaining — canonicalization changes and key rotation produce the identical signal, and the wrong call triggers regulator notification.
